# OnRecord

시안에 맞춰 구현한 Windows용 화면 녹화 데스크톱 앱입니다. Electron과 기본 HTML/CSS/JavaScript를 사용합니다. 기본 창은 980×600이며, 미리보기 상단 제목과 안내 문단을 없애고 저장 위치·타이머·녹화 버튼을 미리보기 아래에 배치했습니다. 하단 저장 경로를 클릭하면 녹화 중에도 저장 폴더를 열 수 있습니다.

## 실행

Node.js 22.12 이상에서 프로젝트 폴더를 열고 실행합니다.

```powershell
npm install
npm start
```

`npm run dist`로 `release/OnRecord 1.2.0.exe` 포터블 실행 파일을 만듭니다. 설치 없이 실행할 수 있으며, 녹화 파일은 기본적으로 Windows 동영상 폴더의 OnRecord 하위에 저장됩니다.

## 사용

전체 화면, 창 선택, 영역 지정 중에서 녹화 대상을 선택합니다. 영역 지정은 별도의 모니터 선택 없이 메인 창이 있는 화면에 960×540 크기의 테두리를 바로 표시합니다. 작은 화면에서는 자동으로 크기를 줄입니다. 상단 손잡이를 드래그해 이동하고, 모서리나 변의 손잡이를 드래그해 크기를 조절합니다. 변경한 영역은 미리보기에 실시간 반영됩니다.

테두리는 화면을 어둡게 가리지 않고 계속 표시됩니다. 안쪽은 Windows 창의 입력 영역에서 실제로 비워 두어 아래 프로그램을 그대로 클릭할 수 있습니다. × 버튼이나 테두리에 포커스가 있을 때 Esc로 영역을 취소합니다. 전체 화면이나 창 선택으로 바꾸면 테두리를 닫습니다. 영역 취소 후에는 대상을 다시 지정해야 녹화할 수 있습니다.

준비 중에는 테두리를 다른 모니터로 옮기면 녹화 대상을 자동으로 전환합니다. 하나의 영역은 한 모니터 안에 유지됩니다. 녹화 중에는 테두리가 빨간색으로 유지되며 같은 모니터 안에서 이동할 수 있습니다. 영상의 해상도를 일정하게 유지하기 위해 녹화 중 크기 조절과 영역 취소는 잠급니다. 종료하면 다시 크기 조절할 수 있습니다.

시스템 소리, 마이크, 해상도, 프레임 수, 화질, 저장 형식과 시작 대기 시간을 설정하고 녹화를 시작합니다. 해상도는 선택한 화면의 비율을 유지하며 설정한 크기 이내로 맞춥니다. 시스템 소리는 선택한 창만의 소리가 아니라 컴퓨터 전체 출력입니다. 마이크나 웹캠을 사용하려면 Windows 개인정보 설정에서 데스크톱 앱의 접근을 허용해야 합니다.

시스템 소리는 음성용 에코 제거·잡음 제거·자동 음량 보정을 끄고 48kHz 스테레오를 요청합니다. 시스템 소리만 켰을 때는 Web Audio 혼합 단계를 거치지 않고 캡처한 트랙을 직접 녹음합니다. MP4는 처음부터 AAC 320kbps를 목표로 녹음하고 저장할 때 오디오를 재압축하지 않고 복사합니다. WebM은 Opus 320kbps를 목표로 녹음하므로 시스템 소리와 마이크를 함께 저장할 수 있습니다.

녹화가 시작되어도 메인 창과 실시간 미리보기는 유지되며, 작은 컨트롤바도 함께 표시됩니다. 메인 창의 녹화 종료 버튼이나 컨트롤바로 종료할 수 있습니다. F9는 시작·종료, F10은 일시정지·재개입니다. 컨트롤바는 드래그해서 옮길 수 있으며 마지막 위치를 저장해 앱을 다시 켜도 복원합니다. 저장된 위치가 화면 밖에 있으면 가까운 모니터의 작업 영역 안으로 보정합니다. 메인 창은 필요할 때 사용자가 직접 최소화할 수 있습니다. 종료하면 화면 캡처·마이크·웹캠과 미리보기 그리기를 멈추고 메인 화면에서 저장 결과를 확인할 수 있습니다. 마지막 미리보기 이미지는 유지되며 다음 녹화 시 장치를 다시 연결합니다.

MP4는 소리 유무와 관계없이 녹화 중 H.264로 직접 압축하고 소리는 AAC로 기록합니다. 비디오 옵션 맨 아래의 **저장 압축**에서 저장 방식을 선택합니다. **빠른 저장**은 재압축 없이 MP4 재생·탐색 정보만 정리하고, **빠른 압축**은 H.264 인코더(`libx264`, CRF 20, fast), **용량 우선**은 같은 인코더의 medium 설정으로 압축합니다. 기본값은 용량 우선이며, 항목 옆 `?` 버튼을 클릭하면 세 옵션의 동작 설명이 팝업으로 표시됩니다. WebM에서는 저장 압축 선택이 비활성화됩니다. 해상도와 프레임 타임스탬프를 유지하고 AAC 소리는 재압축 없이 복사합니다. 빠른 압축·용량 우선으로 저장할 때는 “용량을 줄여 저장하고 있어요”가 표시되며, 영상 길이·화면 변화·PC 성능에 따라 저장 시간이 늘어납니다. 녹화 중 임시 파일 크기는 그대로이며 완성 파일의 용량은 내용에 따라 달라집니다. 완성 전 파일은 `.mp4.finalizing`으로 기록하고 성공했을 때 최종 `.mp4`로 바꿉니다. H.264 직접 녹화를 지원하지 않는 환경에서는 WebM을 선택하도록 안내합니다. 하드웨어 인코더 선택은 Chromium과 그래픽 드라이버에 따르며 모든 환경에서 GPU 사용을 보장하지 않습니다.

WebM은 VP9(미지원 시 VP8)과 Opus로 녹화하고 이름만 바꿔 저장합니다. 두 형식 모두 메모리에 전체 영상을 쌓지 않고 약 1초마다 파일로 나누어 기록합니다. 파일 정리나 쓰기에 실패하면 `.capture.mp4` 또는 `.capture.webm` 원본을 보존하고 경로를 표시합니다. MP4 원본은 조각화된 형식이므로 비정상 종료 시 이미 기록된 완전한 조각의 복구를 시도할 수 있지만, 아직 기록되지 않은 마지막 구간과 디스크 오류로 손실된 데이터까지 보장하지는 않습니다. 저장이 끝나기 전에는 앱을 정상 종료할 수 없습니다.

녹화 모드, 해상도, 프레임, 화질, 파일 형식, 저장 압축, 시작 대기 시간, 시스템 소리·마이크·장치, 웹캠·위치, 저장 폴더와 마지막 영역을 사용자 데이터 폴더의 `preferences.json`에 자동 저장합니다. Windows 기본 경로는 `%APPDATA%/onrecord/preferences.json`입니다. 앱을 다시 실행하면 저장한 설정과 영역 테두리·미리보기를 복원하며, 사용자가 시작 버튼을 눌러 녹화를 시작합니다. 모니터가 사라졌다면 현재 화면 안으로 영역을 맞추고, 이전 프로그램 창이 닫혔거나 이름이 바뀌었다면 대상을 다시 선택하도록 안내합니다. 영역을 취소하거나 다른 모드로 바꿔도 마지막 영역 크기와 위치는 기억합니다.

## 현재 범위

실제 화면 미리보기, 전체 화면·외부 창·영역 캡처, 시스템 소리와 마이크 혼합, MP4/AAC와 WebM/Opus 녹음, 마이크 장치 선택과 입력 미터, 웹캠 오버레이와 네 모서리 위치 선택, 30/60fps 설정, 화질 설정, 카운트다운, 일시정지·재개, 저장 폴더 선택, 영상과 저장 폴더 열기, 녹화 설정과 영역의 재실행 복원을 구현했습니다.

클릭 강조는 준비 중으로 비활성화했습니다. 커서 포함 여부는 Windows 캡처 방식에 따르며 개별 제어를 제공하지 않습니다. 웹캠 위치는 네 모서리 중 선택하며 크기는 영상 너비의 22%입니다. 영상 자르기와 녹화 이력 목록은 구현하지 않았습니다.

Windows 캡처 제외 기능을 앱, 컨트롤바와 영역 테두리에 적용합니다. 원격 데스크톱, 보호된 콘텐츠, 관리자 권한 창 등에서는 Windows와 캡처 드라이버에 따라 결과가 달라질 수 있습니다.

## 검증

```powershell
npm run check
npm test
npm run test:audio
npm run test:preferences
npm run test:saving
node tests/portable-recording.cjs
node tests/compression-options.cjs
```

통합 테스트는 실제 Electron 창과 데스크톱을 사용합니다. 전체 화면 미리보기와 녹화, 녹화 중 메인 창 유지와 실제 화면 변경에 따른 미리보기 갱신, 별도 컨트롤바, 일시정지 시 타이머 유지, 모니터 선택 없이 영역 표시, 손잡이 이동과 크기 조절에 따른 640×360 미리보기, 실제 Windows 입력 영역의 안쪽 구멍, 녹화 중 테두리 유지·이동과 크기 조절 잠금, 영역 취소, 외부 창 캡처, 시스템 소리·마이크를 혼합한 AAC 트랙, MP4/WebM 전체 디코딩을 확인합니다. 앱 창과 영역 테두리 제외는 앱을 녹화 영역 위에 표시한 채 단색 배경과 미리보기·저장 영상의 실제 픽셀을 비교해 검사합니다. 시스템 오디오와 실제 마이크가 있는 Windows 환경이 필요합니다. 테스트 영상, 스크린샷과 결과 보고서는 Git에서 제외된 `work/smoke/`에 저장됩니다.

실물 웹캠의 합성 결과, 여러 모니터 사이의 영역 이동과 서로 다른 배율, 1시간 이상의 실제 연속 녹화, 실제 디스크 공간 부족 시 복구, 녹화 영상에서 컨트롤바가 실제로 제외되는지 여부는 수동 검증이 남아 있습니다. 영역 테두리 제외는 현재 Windows 테스트 환경에서 확인했으며 다른 캡처 환경에서는 추가 확인이 필요합니다. 오디오 테스트는 트랙 생성과 디코딩을 검사하며 소리의 청감 품질을 보증하지 않습니다.

별도 오디오 검사는 실제 Windows 루프백 입력이 48kHz·스테레오이며 음성 보정이 꺼졌는지 확인합니다. 다른 앱의 소리에 영향을 받지 않도록 좌우 440Hz·997Hz 합성 신호를 시스템 소리 전용 녹음 경로에 넣어 MP4/AAC와 WebM/Opus를 각각 녹음합니다. AAC는 녹화 원본과 최종 MP4에서 꺼낸 압축 패킷이 바이트 단위로 같은지, Opus는 원본과 최종 WebM을 디코딩한 샘플이 같은지 검사합니다. 두 방식 모두 일시정지·재개 후에도 같은 비교를 반복하고, 채널·왜곡·클리핑·연속 구간의 50ms 단위 음 끊김과 일시정지 시간이 오디오 길이에서 빠지는지 확인합니다. 이 합성 신호는 스피커로 재생하지 않습니다. 결과는 `work/audio-quality/report.json`에 저장하며 실제 사용자 콘텐츠의 청감 품질 검증과는 구분합니다.

설정 검사는 별도 설정 파일을 사용해 실제 앱을 여러 번 종료·재실행합니다. 녹화 옵션·저장 폴더·640×360 영역·미리보기 복원, 복원 상태에서 WebM 시스템 소리 녹화, 종료 직전 변경 저장, 사라진 모니터의 영역 보정과 전체 화면 대상 복원을 확인합니다. 결과는 `work/preferences/report.json`에 저장됩니다. 테스트는 사용자 설정 파일을 수정하지 않습니다.

압축 옵션 UI 검사는 `node tests/compression-options.cjs`로 실행하며 설명 팝업·창 크기별 배치·WebM 비활성화·재실행 복원을 확인합니다.

저장 경로 검사는 `npm run test:saving`으로 실행합니다. 세 저장 압축 모드의 실제 저장 동작을 검사합니다. H.264 영상 재압축과 용량 감소, 프레임 수·영상 길이 유지, AAC 패킷의 저장 전후 동일성, 소리 포함 1080p/30fps와 무음 1080p/60fps MP4, 전체 디코딩과 중간 탐색·재생, 장치 해제와 재녹화, 파일 마무리 실패 시 원본 보존, H.264 미지원 안내, 녹화 중 강제 종료 후 원본 디코딩을 확인합니다. 별도 사용자 데이터 폴더를 사용하며 결과는 `work/finalization-*/report.json`에 저장합니다. `ONRECORD_TEST_SECONDS=180`처럼 설정하면 첫 녹화 시간을 늘릴 수 있고, `ONRECORD_EXECUTABLE`에 `release/win-unpacked/OnRecord.exe` 경로를 넣어 패키징된 앱을 검사할 수 있습니다. 포터블 실행 파일은 `node tests/portable-recording.cjs`로 별도 실행해 소리 포함·무음 MP4 녹화와 저장을 확인합니다. 자원 사용량·지원 GPU의 NVENC 통계·Windows 작업 표시줄 응답도 기록합니다. 이는 해당 환경과 실행 시간에 한정된 확인이며 모든 장시간 멈춤 현상의 해결을 보장하지 않습니다.

실행 의존성은 `npm audit --omit=dev`에서 알려진 취약점이 없었습니다. 개발용 패키징 도구인 electron-builder의 하위 의존성에서는 moderate 등급 8건이 보고됩니다.

## 참고

화면과 시스템 소리 캡처는 [Electron desktopCapturer](https://www.electronjs.org/docs/latest/api/desktop-capturer/), 창 캡처 제외는 [BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window)의 API를 사용합니다. FFmpeg 실행 파일은 `ffmpeg-static`이 제공하며 배포 시 포함된 FFmpeg 라이선스도 확인해야 합니다.
